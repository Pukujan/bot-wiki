Panel 05 · Who repairs, who judges.

Klerik repairs. The validator judges.

See the run log→

What Klerik does

Klerik reads every BOT.md in the fleet, checks the hold points are still set, and repairs the index when a file moves. It can edit the bots.

What Klerik cannot do

It cannot edit .system/validate.py — the validator that judges its own work.

Hold point missing

If a hold point is missing, Klerik restores the line and writes the repair to the audit log.

Validator fails

If the validator fails, the loop stops and the fleet stays as it was.

Division of labour

Klerik

Reads BOT.md · restores hold points · repairs the index

no write access

.system/validate.py

Judges the work · read-only to Klerik

One rule

No bot releases its own hold.

Panel 06 · Questions

faq · 6 entries
Can a bot release its own hold?
No. Release is a human edit to .system/holds.md or a BOT.md hold_points line; the validator rejects a bot writing its own flag.
What happens to work that trips a hold?
It is staged, not lost — the draft, form or file path is saved and the audit log records the trip.
Do the four hold points ship set?
Yes. Every new bot starts with spend, publish, submit and delete held.
Where does the log live?
Every trip and release is appended to the bot's .system/holds.md and mirrored into the audit log above.
Can I add a fifth hold point?
Yes — add the line to BOT.md, and the validator reads it on the next pass.
Does Klerik bypass the interlocks?
No; Klerik is a bot and the same four apply.
